# v0.1.0 安全边界

本页描述保留的过滤器原型。v0.2.0 新增的菜单栏与受控运行组件见 [运行模型](V0.2.0-RUNTIME.md)；这些组件没有消除本页列出的系统过滤缺口。

## 目标与当前实现

最终目标是只有 Claude 的受保护流量可以使用指定代理；发现直连或保护故障时，先阻断网络，再立即终止本机受保护任务。

v0.1.0 只实现其中的**签名识别与新流过滤实验**。它没有独立的网络拒绝边界，没有保证扩展崩溃后仍然拒绝流量，也没有终止任务。因此不能用它替代现有防火墙或保护真实 Claude 会话。

## 身份

用户选择已签名可执行文件。Security.framework 检查静态签名并提取 designated requirement。
过滤器通过 `sourceAppAuditToken` 和 `sourceProcessAuditToken` 解析系统提供的动态代码身份，匹配登记的 requirement。
任何一项匹配即视为目标；两项都能解析且不匹配才视为其他程序。缺失/失败的归属标记为 `UNATTRIBUTED`。

不使用 `pgrep`、名字包含 `claude`、路径子串、可复用 PID 或定时扫描作为身份依据。
build 2 的自动发现固定校验 `anchor apple generic` 和 Team ID `Q6L2SF6YDW`，该 ID 来自本机 Claude 2.42304.2 经验证的 Developer ID 签名。桌面主包还须满足 `com.anthropic.claudefordesktop`。
若发布者签名改变，扫描拒绝登记并报告，不自动放宽条件。每个程序保留具体 designated requirement 并附加发布者约束，不使用 Team ID 通配匹配所有 Anthropic 程序。
扫描只遍历已验证 App 包内的可执行普通文件，不跟随包内符号链接；包外链接报告为未覆盖。识别薄/通用 Mach-O，动态库不作为进程身份，脚本及读取/验证错误均报告。
原生 CLI 仅在文档列出的标准路径寻找，允许解析安装器生成的符号链接，但仍须签名校验。路径只是发现入口，不是过滤器匹配依据。
手动添加仍允许操作者明确选择其他已签名程序；登记正确二进制是实验操作者的责任。
ad-hoc 签名通常按代码哈希固定版本；重建或升级后需重新登记。
开发者签名的要求可能跨版本匹配；实际覆盖范围由该指定签名要求决定。

父进程被登记**不意味着子进程自动被登记**。本版本不声称支持继承、重归属进程、MCP 外部代理、系统服务代发或云端任务。
把通用解释器登记为目标会影响它运行的无关任务。
磁盘扫描不能证明运行中进程覆盖：运行时更新、下载、虚拟机、包外工具和磁盘文件被替换仍需独立验收。预览清单不持久化；一次扫描只添加身份，不自动删除之前手工登记的身份。重新建立清单时先清空再扫描。

## 网络策略

- `blockAll`：拒绝已识别目标的全部新流。
- `proxyOnly`：只允许该目标发起的 TCP 连接到精确配置的回环地址和端口。
- 不接受 DNS 名字作为允许端点；支持标准数值 IPv4/IPv6 和 IPv4-mapped IPv6。
- 目标的其他回环端口、其他 127/8 地址、LAN、外网、UDP、未知协议、缺失端点和入站连接均拒绝。
- IPv4 127/8 与 IPv6 ::1 有显式系统过滤规则；其余流量使用 `.filterData`。
- 无关程序放行。无法归属的流量记录覆盖缺口并放行，避免全机断网。

这是一层**过滤器**，不是透明代理。它不转换协议，不设置 Claude 环境变量，不替用户修改代理规则。
允许访问本地代理端口并不证明请求经代理隧道，更不证明出口在美国。
其他程序抢占同一端口、代理自身 DIRECT 回退、配置被外部修改都属于未解决问题。

## 生命周期与故障

策略在启动时解析、验证和编译；无效配置导致启动失败。失败意味着未建立保护，不能视为已安全阻断。
配置按一次实验固定，界面拒绝在启用状态下重新保存策略。
代理端点流保留数据回调和有限跟踪表（最多 4096 条），超过上限拒绝新目标流。
正常停用请求将已跟踪流改为丢弃；这不证明已排队数据、已释放的字节或外部操作已经撤销。

扩展启动前已存在的连接、扩展异常退出/挂起、授权撤销、升级替换、配置卸载、系统重启没有得到跨状态拒绝保证。
界面只有“配置启用”状态，没有伪造“保护正常”的绿灯；配置状态不是数据面健康证明。
本版本不自动替换正在运行的系统扩展。

## 后续版本的准入条件

1. 在真实设备上证明目标新流、已有流和故障期间的行为；用接收端证据或抓包检验。
2. 明确 DNS、系统代发、子进程与桌面 Helper 的覆盖；无法覆盖的情形不能静默放行后宣称安全。
3. 专用代理只允许固定节点和明确策略，消除 DIRECT 回退。
4. 独立守护器确认保护有效后才允许启动；故障时阻断、关闭连接并可靠地终止本机任务。
5. 测试守护器与扩展分别/同时崩溃；不能用“通常很快重启”替代安全边界。
6. 如果原生网络扩展无法满足故障语义，改变架构，采用受控隔离运行环境。

## 隐私

运行日志仅记录流 UUID、动作和状态，不记录请求正文、认证信息、目标域名或代理密码。
不要把完整系统日志上传到公共 issue。描述文件与签名材料排除在 Git 跟踪之外。
