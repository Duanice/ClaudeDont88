# v0.2.0 运行模型与限制

## 范围

本版本实现菜单栏、私有代理配置、独立监督进程、受控进程组强退，以及默认拒绝真实 Claude 启动的检查链。不是已完成防泄漏验收的产品。

`LaunchConditions` 要求代理可用、上游验收、完整身份覆盖、系统拦截证明；桌面还需桌面代理路径证明。生产代码目前只有代理可用性检查，其他证明没有接入，因此所有真实 Claude 启动都拒绝。配置启用、描述文件存在、IPC 中伪造布尔字段均不能解锁。

CLI 后端保留签名检查及覆盖大小写 HTTP(S)_PROXY、清空 NO_PROXY 的非交互启动路径，但当前不可达、输出尚未接入产品界面。桌面启动适配未实现。不能仅补一张证书或把布尔值改成 true 就将版本判为可用。

## 控制关系

```text
菜单栏 App ── 私有匿名管道 ── guard-runtime
                                ├─ 独立 mihomo 进程组
                                ├─ 出口检查 curl 进程组
                                └─ 受控任务进程组（目前仅不联网演练开放）
```

监督进程不开放网络管理端口。控制消息限 64 KiB，错误消息触发关闭；控制管道 EOF 或状态管道写入失败同样清理会话。
UI 只关闭窗口时不会断开；选择退出或 UI 进程死亡才会关闭管道。

执行文件先经过 Security.framework 验签。`posix_spawn` 创建独立进程组、关闭无关继承描述符，先挂起；再校验该子进程动态签名，匹配后 SIGCONT。
进程组首进程在停止前不被回收，保留其 PID，避免先回收再向同号的新进程组误发信号。

停止顺序：停止并等待代理首进程退出 → 停止检查进程 → SIGKILL 受控任务及原进程组 → 删除本次临时目录。重复停止幂等。
这关闭的是本应用的代理通道，不等于操作系统已阻断目标的全部其他网络路径。

## 代理配置与凭据

- 使用用户已安装的 mihomo，独立目录、端口及进程；不捆绑内核，不修改系统代理或现有 Clash 配置。
- 仅一个具体上游 `CLAUDE_ONLY`，只有 `MATCH,CLAUDE_ONLY` 规则。无备用组、无 DIRECT 规则、无 provider 或外部控制 API。
- 绑定 `127.0.0.1`，随机本地认证，显式清空跳过认证的地址段。关闭 TUN、DNS 监听与嗅探。
- 上游要求数值 IP；TLS 可按节点设置服务器名，证书验证固定开启。
- 未加载用户订阅。HTTP/HTTPS、SOCKS5、SS、Trojan 的配置生成经过单元测试；真实内核夹具只验证 HTTP 上游，其他协议仍需真实节点验收。
- 非密码配置位于 `~/Library/Application Support/ClaudeDont88/proxy-profile.json`；密码位于本机钥匙串。
- 内核需要的密码会写入当前会话的临时 JSON：目录 0700、文件 0600、正常关闭后删除。不是“秘密从不落盘”。监督进程被强杀、断电等情况可能留下临时文件。
- 每 15 秒以固定显式代理执行一次 HTTPS 出口查询，连接超时 3 秒、总超时 5 秒、响应限 64 KiB；curl 必须成功退出且响应声明成功及美国国家码。无重定向或直接请求回退。
- 查询使用第三方 `ipwho.is`，该服务可看到代理出口 IP。结果受 IP 数据库准确性影响，不证明所有流量或故障期间都从美国出去。

## 尚未解决

1. 系统过滤健康证明与故障原子性：签名条件仍缺失，当前扩展还存在未归属流量的覆盖缺口。
2. 进程脱组、守护化、共享后台 supervisor、虚拟机、远程任务。原组 SIGKILL 不证明任意后代都结束。
3. 监督进程本身被 SIGKILL/卡死/崩溃后的孤儿进程与重启恢复。UI 发现监督进程异常消失时会保留故障，不用新会话覆盖未知状态。
4. 检查不是实时信号；失败可能在一个检查周期和超时后才发现。即使立即 SIGKILL，也不能撤回已释放字节。
5. 专用代理的单规则不会禁止上游服务自身或其他应用走 DIRECT；真实节点仍需验收。
6. 桌面 Code 的凭据/设置范围、交互式 CLI 界面、完整输出、安全恢复、自动更新及公证分发。

因此不开放真实 Claude 启动。下一阶段应接入可验证的底层阻断证据，再逐项解决上述覆盖缺口，而不是添加“我已确认安全”的开关。
