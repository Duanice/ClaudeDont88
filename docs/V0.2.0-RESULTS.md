# v0.2.0 验证记录

2026-10-20；App 版本 0.2.0，构建号 1。环境：Apple silicon、macOS 26.5.2、Xcode 26.6、Swift 6.3.3。真实代理夹具使用本机已安装的 mihomo v1.19.29。

**结论：菜单栏、拒绝启动门禁、受控进程清理和专用代理的局部故障试验通过。真实 Claude 受保护启动仍未开放，系统防泄漏验收未完成。**

发布后补充了已安装 Claude 2.42304.2 的实际启动、强退和进程组观察。外层测试沙箱中的完整桌面启动失败；不能标记代理路径通过。见 [真实 Claude 实机记录](V0.2.0-REAL-CLAUDE.md)。

## 已通过

| 检查 | 结果及范围 |
|---|---|
| Swift 测试 | 33 项通过：原有 25 项、5 项代理配置/启动条件测试、3 项真实进程所有权测试 |
| 四种协议配置生成 | 每种只含一个上游、固定规则、回环监听和认证；无 DIRECT 备用组或系统路由开关 |
| 启动条件 | 32 组布尔组合；缺一项即拒绝，不把代理可用当作过滤有效 |
| 真实进程管理 | 独立 PGID、动态签名检查、SIGKILL、重复停止、退出状态与先停止后回收；无关进程不受影响 |
| 伪造 IPC 条件 | 发送 `filterVerified=true` 等额外字段不能绕过真实启动拒绝 |
| 手动强退 | 演练首进程及同组子进程停止 |
| UI 控制管道 EOF | 清理演练进程组 |
| 无效消息 / 状态管道中断 | 清理演练进程组并退出监督进程 |
| 专用代理被强杀 | 监督进程收到退出事件，终止演练进程组并删除临时配置 |
| 临时文件权限 | 会话目录 0700、配置文件 0600 |
| 真实 mihomo HTTP 上游 | 使用生成的配置，请求经回环上游返回标记；无认证请求失败 |
| 上游断开 | 经专用代理请求失败，直接接收端没有收到请求；直接正向对照仍能返回标记 |
| 菜单栏与 GUI | 真实点击桌面启动后显示缺失条件；演练/强退成功；关闭窗口保留菜单；菜单重新打开面板；退出 App 清理演练进程组 |
| Release / 签名完整性 | 四个可执行目标生成；整个预览包 `codesign --verify --deep --strict` 通过 |
| 原有网络基线 | TCP/UDP × IPv4/IPv6 echo、拒绝主机名和关闭端口失败均通过 |

`runtime_baseline.py --engine ...` 共输出 8 项检查；没有真实节点时仅使用本地 HTTP 上游与接收端，不访问 Anthropic，也没有启动 Claude。

## 未验证或未完成

- 系统扩展实机加载与真实流量阻断：缺少相应签名/描述文件，BLOCKED。
- 真实 Claude CLI：未找到独立原生 CLI；启动门禁保持关闭。
- 桌面 Claude Code：代理路径适配和后台/虚拟机覆盖尚未实现，启动门禁保持关闭。
- 美国节点实际配置、连续出口检查、TLS/SOCKS5/SS/Trojan 真实上游：未使用用户凭据开展试验。HTTP 回环试验不能替代这些验证。
- 钥匙串持久化接口已实现，但没有用用户节点密码进行保存/升级后的访问测试。
- 监督进程被强杀/卡死后的清理、重启恢复、脱离进程组的后代、系统代发流量、检测延迟下的字节泄漏：未完成。
- 交互式 CLI、任务输出界面、桌面完整运行链、自动更新、签名/公证分发：未完成。

这些限制是继续开发的真实前置工作，不能通过勾选“已验收”跳过。详情见 [运行模型](V0.2.0-RUNTIME.md)。

## 复现

```sh
swift test
python3 scripts/build_app.py
python3 scripts/probe_baseline.py build/ClaudeDont88.app/Contents/Helpers/guard-probe
python3 scripts/runtime_baseline.py build/ClaudeDont88.app/Contents/Helpers/guard-runtime
# 可选：使用本机已安装的内核，仅运行回环夹具
python3 scripts/runtime_baseline.py build/ClaudeDont88.app/Contents/Helpers/guard-runtime \
  --engine '/Applications/Clash Verge.app/Contents/MacOS/verge-mihomo'
```

GitHub runner 不包含第三方内核，CI 不运行最后一项；本机补充结果单独记录。GitHub CI 状态以对应提交的 Actions 为准。
