# v0.3.0：任务守护与已观察后代清理

本次交付独立任务守护、控制心跳、审计身份终止及真实故障测试。**仍为实验预发布；正常桌面 Code 代理适配、完整后代覆盖和系统防泄漏尚未完成。真实 Claude 启动门禁保持关闭。**

## 控制与停止

```text
菜单栏 App -- 控制管道 / 每秒心跳 --> guard-runtime
                                      |-- guard-worker -- mihomo
                                      |-- guard-worker -- curl 出口检查
                                      `-- guard-worker -- 受控任务
```

每个 worker 都是独立进程组首进程，实际任务加入该组。worker 直接拥有并回收任务，监督进程直接拥有并回收 worker。停止前保留首进程 PID，先终止所属组再回收，避免向重用后的进程组发送信号。

- 任务先挂起，核验动态签名、取得审计身份，报告 PID 后等待监督进程确认。没有确认时不会执行目标代码。
- 监督进程每 500 ms 向 worker 发送心跳。管道 EOF 立即触发清理；超过 3 秒没有心跳，worker 清理任务、临时代理配置，再结束自身组。检查周期为 250 ms，实际调度会影响时延。
- UI 每秒向监督进程发送心跳；超过 5 秒没有控制消息，监督进程停止会话。UI 连续 4 秒收不到回执时也会关闭控制管道，并尝试按审计身份终止失联的监督进程。
- worker 自身异常退出时，仍活着的监督进程会清理其原组，并停止其他会话组件。手动停止时最多等待约 1 秒回执，然后对仍持有首进程的组执行强退。
- 缺少 worker 清理回执或已登记后代终止失败时，报告“清理状态未知”，锁定本次监督会话的新启动请求，不把没有回执显示成成功。
- 代理退出或出口检查失败仍停止任务。出口查询仍每 15 秒一次、最长 5 秒；它不是实时直连检测。

这些是用户态故障处理时间，**不是字节泄漏上界**。监督进程与 worker 同时失效、worker 脱组、内核卡住、系统重启等情况仍需要系统级阻断和恢复机制。

## 进程归属

每 50 ms 观察已登记父进程的子进程。登记时核对父子关系、创建时间及审计身份；登记后使用包含 PID 代次的 audit token 发出终止信号。进程已消失或 PID 被重用时拒绝向新代次发送信号，不回退为按名称或裸 PID 结束被接管的进程。

对于已知会守护化的程序，可额外指定：**精确可执行路径 + 代码签名要求 + 含本次私有会话路径的完整参数**。实际 Claude 测试用此规则识别本次 profile 的 crashpad；普通后台进程、其他 profile 的 Claude 和其他会话不匹配。路径比较统一处理 macOS 的 `/var` 与 `/private/var` 别名。

使用 `task_name_for_pid`、`TASK_AUDIT_TOKEN` 和动态查找的 `proc_signal_with_audittoken`；后者属于 libproc 接口，后续系统兼容性需要继续验证。接口缺失或发信号失败会报告错误，不用裸 PID 代替。实测旧代次令牌返回 ESRCH，目标保持运行。

**这不是完整的内核后代追踪。** 轮询仍可能漏掉快速 fork/exec、未匹配规则的守护化进程、共享 supervisor、虚拟机和系统代发流量。每个追踪器最多保留 512 个身份，已知程序接管扫描最多读取 8192 个 PID。启动条件中的完整身份覆盖证明仍不成立。

## 桌面兼容定位

对 Claude 2.42304.2 的实机复测新增标准错误采集，明确捕获：

```text
sandbox initialization failed: Operation not permitted
Failed to initialize sandbox.
```

错误发生于外层 `sandbox-exec` 测试隔离下，Electron Helper 尝试初始化自身沙箱。GPU 和网络服务随后反复退出，主进程退出状态为 5，测试代理请求数为 0。原用户实例保留。

因此废弃将外层 Seatbelt 包裹作为正常桌面启动方案的设想；当前脚本仅用于复现兼容失败和进程观察。没有添加 `--no-sandbox`、没有把无外层阻断的启动伪装成受保护启动。下一步正常桌面运行需在独立的系统流量阻断已可验证时开展，随后还要解决桌面代理认证、实际 Code 会话、后台及虚拟机路径。

现有普通 Apple ID 环境缺少本项目系统扩展所需签名和描述文件。拥有签名也不会自动解锁：过滤健康、完整身份、上游故障和桌面路径证明仍需实际实现与测试。

## 验证与分发

见 [v0.3.0 验证结果](V0.3.0-RESULTS.md)。标准构建会生成并签名五个可执行目标，包括新增的 `guard-worker`；UI 仍为菜单栏预览。

`guard-worker` 是无特权的内部管道协议执行器，不是可独立使用的“受保护 Claude 启动器”。它只接受已有权限范围内的任务，没有管理员权限，也没有网络控制端口。用户配置、代理密码和完整诊断日志不上传仓库。

原始依据：[Apple libproc 实现](https://github.com/apple-oss-distributions/xnu/blob/main/libsyscall/wrappers/libproc/libproc.c)、[Chromium macOS 沙箱设计](https://chromium.googlesource.com/chromium/src/+/a4deb0bdf0f38a40d4ff4624eddf0fdfc0b05b9d/sandbox/mac/seatbelt_sandbox_design.md)。
