# v0.2.0 真实 Claude 实机补充测试

2026-10-20，Apple silicon / macOS 26.5.2，已安装官方 Claude **2.42304.2**。

**已经实际启动并终止了 Claude 测试实例；桌面联网启动验收失败，真实 Code 任务和系统防泄漏仍未通过。** 本次补充测试脚本和记录，不改变 v0.2.0 发布包，也不开放产品的启动门禁。

## 正在运行的用户实例

检查时有 9 个 Claude 相关进程。一次 `lsof` 抽样看到 13 条 TCP 连接，远端均为 `127.0.0.1:7897`，与当时的系统代理端口一致。这只能证明这次抽样看到的连接路径，不能证明代理出口、历史连接、DNS、UDP、IPv6、桌面 Code 后台或虚拟机均受控。

真实 `chrome_crashpad_handler` 的父进程为 PID 1，PGID 与 Claude 主进程组不同。因此“结束主进程组”不是完整进程树终止的证明。

没有终止用户正在使用的实例，没有提交对话或 Code 任务，没有登录测试账号，也没有更改系统代理。

## 实际启动与强退

临时驱动直接编译产品中的 `OwnedProcess.swift` 和 `CodeIdentity.swift`，不复制一份模拟的进程管理实现。启动前验证 Anthropic 发布者及桌面 bundle ID；随后使用产品相同的挂起启动、动态签名核验、独立 PGID 和 SIGKILL 路径。

测试实例使用新建 HOME、用户数据目录、CLI 配置目录及临时目录。额外的 `sandbox-exec` 测试规则只放行测试代理端口的 TCP 连接及本地 Unix IPC，并拒绝读写用户的 Claude 配置目录。代理对收到的请求一律返回 503，不转发到互联网，不记录请求地址、凭据、头部或正文。这是局部测试隔离，不能代替产品 Network Extension 或证明系统代理服务的代发流量受控。

| 检查 | 观察结果 |
|---|---|
| 本机网络对照 | 不受测试沙箱限制的直连接收端可达；同一接收端在测试沙箱内不可达；指定测试代理端口可达 |
| 第一次真实实例 | 创建主进程及辅助进程，观察到独立的 crashpad 进程组 |
| 第一次强退 | SIGKILL 后主进程退出状态为 9；从发送停止到回收主进程约 24.6 ms；1 秒后未发现已观察到的测试进程残留 |
| 首次启动局限 | 没有测试代理请求。后续调用栈采样发现主线程等待钥匙串授权，未进入正常联网阶段 |
| 临时钥匙串适配 | 仅空白测试实例增加 `--use-mock-keychain`，不向真实使用配置推荐此参数 |
| 完整启动尝试 | 日志进入 app-ready，并报告代理解析为 proxied；随后 GPU 与 Network Service 反复以 6 退出，主进程以 5 退出；测试代理请求仍为 0 |
| 结论 | **联网启动失败，不能视为代理路径通过**；应用自发崩溃也不能算强退测试成功 |
| 原有实例 | 各次测试结束时，原先 9 个进程仍在，命令行与测试前一致 |

24.6 ms 只是一次本机主进程终止测量，不是泄漏检测时延、所有子进程终止上界或性能保证。虽然本次 crashpad 随主进程结束后自行退出，产品没有对脱离 PGID 的进程提供可靠的强制结束机制。

外层测试沙箱下的启动失败说明这套测试方式尚不能验证正常桌面运行链，不能推断正常安装的 Claude 有相同故障，也不能用关闭产品门禁或关闭 Electron 安全沙箱把结果改成“通过”。

## 复现

此测试需要本机安装官方 Claude，只运行于人工明确要求的实机测试中。不会由 CI 或普通单元测试自动启动第三方 App：

```sh
mkdir -p local
python3 scripts/claude_desktop_smoke.py \
  --app /Applications/Claude.app \
  --report local/claude-desktop-report.json
```

脚本编译测试驱动，最多观察约 30 秒，然后关闭控制管道以清理自己的进程组。报告只保留版本、PID/PPID/PGID、计数与测试状态；临时目录正常结束后删除。

退出码 `0` 仅代表该次启动/拒绝代理请求/停止的局部测试通过，**不代表防泄漏通过**。退出码 `2` 表示真实启动验收不完整；提前崩溃、没有代理请求、停止失败或存在残留均不能报成功。当前本机的完整启动尝试为 `2`。构建或隔离前置条件异常会直接失败。

需要本地排障时可加 `--diagnostics local/claude-desktop.log`；完整日志不要提交公共仓库。测试钥匙串选项的用途参见 [Electron 官方测试修复说明](https://releases.electronjs.org/pr/53790)。
